# law-links

FastAPI-сервис, выделяющий из русского текста юридические ссылки вида `пп. 1 п. 1 ст. 374 НК РФ` и возвращающий их структурой `law_id / article / point_article / subpoint_article`. Условие задания: [docs/TASK.md](docs/TASK.md).

- Опрос для проверки качества на новых текстах: [huggingface.co/spaces/fpakhurov/law-links-survey](https://huggingface.co/spaces/fpakhurov/law-links-survey)
- Открытый датасет ответов: [huggingface.co/datasets/fpakhurov/law-links-votes](https://huggingface.co/datasets/fpakhurov/law-links-votes)

## Быстрый старт

```bash
docker build -t law-links-service .
docker run -d -p 8978:8978 --name law-links-container law-links-service

curl -X POST "http://localhost:8978/detect" \
     -H "Content-Type: application/json" \
     -d '{"text": "Согласно статье 23 Налогового кодекса и ст. 145 Гражданского кодекса"}'
# {"links":[{"law_id":15,"article":"23",...},{"law_id":5,"article":"145",...}]}

docker stop law-links-container && docker rm law-links-container
docker rmi law-links-service
```

Swagger: http://localhost:8978/docs, проверка состояния: `GET /health`. Словарь законов берётся из `law_aliases.json` рядом с `main.py`, как в шаблоне задания, если он там есть, иначе из `data/law_aliases.json`; путь можно задать переменной `LAW_ALIASES_PATH`.

Локально без Docker (Python 3.11+):

```bash
pip install -r requirements-dev.txt
python main.py            # или: make run
make test                 # pytest
make eval                 # precision / recall / F1 на dev: tests/gold.json и tests/gold_real.json
make speed                # 2000 текстов через /detect против лимита проверки (5 минут)
make audit                # отчёт о качестве law_aliases.json -> docs/aliases_audit.md
```

## Как работает

Метод выбран по итогам исследования: сравнивались правила, tf-idf, fuzzy matching, n-граммные модели, word2vec, HMM, CRF и наивный Байес ([docs/RESEARCH.md](docs/RESEARCH.md)).

1. `normalize` приводит кавычки, `ё`, неразрывные пробелы и тире к одному виду, латинские буквы-двойники в кириллических словах (`cт.`, `УK`) - к кириллице; длина текста не меняется, поэтому позиции совпадают с исходником.
2. `chains`: скрытая марковская модель второго порядка размечает токены ролями (маркер или значение подпункта, пункта/части, статьи, отбрасываемого уровня), декодирование алгоритмом Витерби. Модель обучена на синтетических ссылках, вставленных в предложения судебных решений (`research/train_chains.py`), и лежит в `data/chain_hmm.json` (15 КБ). Так разбираются `ст. 19.5. КоАП`, `п. «б» ч. 1 ст. 58`, `п. 6 ч. 1 ст. 24.5`, `подпунктом "г" пункта 6 части 1 статьи 81`, `части первой`, `абз. 1 ст. 394`, `ст.ст. 194 -199`, а также порядок «статья -> часть»: `Статья 20.4 ч. 1 КоАП`, `ст. 105 ч. 2 п. «а» УК`, `ст. 12.8 ч. 1, ст. 12.26 ч. 2 КоАП`. Шум: приклеенный маркер отделяется (`спп. 1`, `Согласностатье 16`), маркер с опечаткой (`сттаьи`, `пбнкту`) остаётся маркером, повторная точка (`ст..161`) и точка после номера в перечне (`487., 516.`) не сбивают уровень, цепочка без слова-маркера (таблица чисел, `т. 10, л.д. 5`) отбрасывается.
3. `resolver`: правый контекст цепочки режется на префиксы из 1-20 слов, префиксы и 18.7k алиасов лемматизируются pymorphy3 и сравниваются косинусом tf-idf по символьным 3-5-граммам. Лучшая пара выше порога 0.85 даёт закон. Точное совпадение префикса с названием берётся без tf-idf, сходство префиксов кэшируется. Это находит склонённые формы, `КоАП` без `РФ`, `Закона N 27-ФЗ`, старые названия законов, дату и номер между цепочкой и названием. Неизвестное слово в одной правке от слова из названий исправляется заранее: `Трудовго коедкса` -> `Трудового кодекса`.
4. `context`: номер закона, общий для нескольких актов (`ФЗ №63-ФЗ`: 246 и 396), выбирается наивным Байесом по словам вокруг ссылки; `ст. 19.5 названного Кодекса` получает последний упомянутый кодекс.
5. В перечне `ч. 6 ст. 15, ст.ст. 64 и 73 УК РФ` цепочка без закона получает закон следующей.
6. Перечисления раскрываются декартовым произведением: `пп. 1, 2, 3 п. 2 ст. 3 НК РФ` -> 3 объекта.

Старт сервиса ~3 с (лемматизация алиасов и tf-idf). Скорость под ограничение проверки (4 бенча по 500 текстов за 5 минут): 2000 текстов по ~3 тыс. символов через `/detect` - 11-16 с; текст из условия (4 тыс. символов, 34 ссылки) - 55 мс при пустом кэше, 7 мс при прогретом; худший случай, 2000 таких текстов с пустым кэшем, - около 2 минут (`make speed`).

## Принятые решения

| Случай | Поведение |
|---|---|
| `п. 10 АПК` (нет статьи) | `article: null, point_article: "10"` |
| закона нет в словаре (`рандомного кодекса`, `ФЗ №20-456`, Конституция) | ссылка не возвращается |
| алиас принадлежит нескольким законам (580 случаев) | закон выбирается по контексту (наивный Байес), без контекста наименьший id |
| пункт внутри части (`п. 6 ч. 1 ст. 24.5`) | часть в `point_article`, пункт в `subpoint_article` |
| четыре уровня (`пп. «г» п. 6 ч. 1 ст. 81`) | две нижние единицы, часть отбрасывается |
| диапазоны (`ст. 167-171`) | одна строка без пробелов |
| абзацы, примечания | отбрасываются |
| `часть` | пишется в `point_article` |
| повторы одной ссылки | сохраняются, порядок как в тексте |

## Качество

Три эталона, все размечены вручную. dev использовался для разработки, test отложен: 8 случайных фрагментов решений, размечены до запуска на них любых методов, прогон один раз для финалистов.

| Эталон | Что внутри | Ссылок | Первая версия (правила) | Этот сервис |
|---|---|---|---|---|
| `tests/gold.json` (dev) | текст из условия задания и 10 контрольных случаев | 44 | F1 1.000 | P 0.978, R 1.000, F1 0.989 |
| `tests/gold_real.json` (dev) | 6 судебных актов с sudact.ru и типовой договор (отрицательный пример) | 212 | F1 0.820 | P 0.991, R 0.991, F1 0.991 |
| `tests/gold_test.json` (test) | 8 случайных фрагментов решений из корпуса | 103 | P 0.885, R 0.524, F1 0.659 | **P 0.970, R 0.942, F1 0.956** |

Устойчивость к шуму (`make noise`, `research/noise.py`): тексты портятся опечатками, латинскими буквами, склейкой слов, лишними точками и пробелами, ответы те же. F1 при всех видах шума сразу:

| | v1.1.0 | v1.2.0 |
|---|---|---|
| dev | 0.820 | 0.979 |
| test | 0.659 | 0.932 |

По видам шума - [REPORT.md, раздел 4.7](REPORT.md).

`make eval` считает dev, `python -m scripts.eval --gold tests/gold_test.json` считает test. Тексты лежат в `tests/real/` и `tests/test_texts/`, источник каждого указан в эталоне. Судебные акты и типовые договоры, утвержденные постановлением Правительства, не охраняются авторским правом (п. 6 ст. 1259 ГК РФ). Ход исследования и разбор ошибок в [docs/RESEARCH.md](docs/RESEARCH.md) и [docs/NOTES.md](docs/NOTES.md).

## Проверка law_aliases.json

`make audit` пишет [docs/aliases_audit.md](docs/aliases_audit.md). Что нашлось в текущей версии:

- у Семейного кодекса (id 8) сокращения записаны с латинской `C` (`CК РФ`); сервис это компенсирует, в данных стоит исправить;
- 580 алиасов вида `ФЗ №7-ФЗ` принадлежат сразу нескольким законам;
- нет Конституции РФ и ФЗ «О банках и банковской деятельности»; нет сокращения `КАС РФ` (id 18);
- около 300 алиасов с непарными кавычками или пометкой редакции в названии;
- 37 коротких названий в кавычках (`«О связи»`, `«О рекламе»`) без номера и даты.

## Разметка и опрос

Основной способ оценки на новых текстах - опрос одногруппников ответами «да/нет» на найденные ссылки и кандидатов на пропуск ([docs/SURVEY.md](docs/SURVEY.md)).

- **Опрос**: [fpakhurov/law-links-survey](https://huggingface.co/spaces/fpakhurov/law-links-survey) на Hugging Face Spaces, код в `space/`. Участник придумывает имя и за одно-два нажатия отвечает на вопросы двух видов: верно ли программа поняла найденную ссылку (и если нет, что неверно: закон, статья или часть/пункт) и есть ли ссылка во фрагменте, который программа пропустила. Каждый 8-й вопрос контрольный, с известным ответом.
- **Датасет**: [fpakhurov/law-links-votes](https://huggingface.co/datasets/fpakhurov/law-links-votes), CC-BY-4.0. `items/survey1.jsonl` - 359 вопросов по 40 фрагментам судебных решений (273 проверки найденных ссылок, 46 кандидатов на пропуск, 40 контрольных), собранных версией `v1.0.1`, `votes/*.jsonl` - ответы: вопрос, ответ, имя участника, случайный номер браузера, время. Ответы дописываются во время опроса.
- **Анализ**: `hf download fpakhurov/law-links-votes --repo-type dataset --local-dir annotation/data/survey/survey1/votes`, затем `python -m annotation.survey analyze survey1 --votes annotation/data/survey/survey1/votes` - точность с доверительным интервалом, типы ошибок, полнота относительно пула кандидатов, согласие участников. Вопросы собираются `python -m annotation.survey build`.

Полные эталоны можно собирать в приложении на Gradio ([docs/ANNOTATION.md](docs/ANNOTATION.md)):

```bash
pip install -r annotation/requirements.txt
python -m annotation.app                                  # http://127.0.0.1:7860
python -m annotation.make_tasks train2 --mode suggest     # новый пакет из корпуса
python -m annotation.export test2 --out tests/gold_test2.json   # согласие разметчиков и экспорт
```

Пакеты: `test2` (12 документов, без подсказок модели) - второй независимый test (его документы никто не видел, годится и для `v1.1.0`); `train1` (10 документов, с подсказками) - обучающая разметка. Документ, размеченный двумя людьми по-разному, в эталон не попадает, пока его не разметит `adjudicator`.

## Структура

```
main.py                 FastAPI: lifespan, DI, /detect, /health
law_links/
  normalize.py          нормализация без изменения длины
  chains.py             HMM-разметчик цепочек пп./п./ч./ст. и декодирование
  lemmas.py             токены и леммы pymorphy3
  resolver.py           закон цепочки: tf-idf по символьным n-граммам + косинус
  context.py            отсылки «названного Кодекса», наивный Байес для общих номеров
  extractor.py          LinkExtractor (Protocol) и Extractor
  schemas.py            LawLink, TextRequest, LinksResponse
data/law_aliases.json   база законов
data/chain_hmm.json     параметры HMM
tests/                  pytest, эталоны gold.json, gold_real.json, gold_test.json
scripts/eval.py         метрики на эталоне
scripts/speed.py        скорость против лимита проверки
research/noise.py       шумовой бенч: dev с опечатками, склейками, латиницей
scripts/audit_aliases.py  аудит базы законов
research/               корпус, выбор test, обучение HMM, бенчмарк (не входит в образ)
annotation/             разметка и опрос: пакеты задач, вопросы опроса, анализ ответов (не входит в образ)
space/                  приложение опроса для Hugging Face Space
docs/PLAN.md            план, включая фазу 2 (датасет, Space, NER)
docs/RESEARCH.md        исследование методов и результаты
docs/ANNOTATION.md      правила и порядок разметки
docs/SURVEY.md          опрос да/нет: вопросы, развёртывание, анализ
REPORT.md               технический отчёт
docs/NOTES.md           журнал наблюдений для техотчёта
```

### Исследование методов (docs/RESEARCH.md)

- `[важное]` Сервис переведён на победителя исследования: HMM второго порядка для цепочек, tf-idf по символьным n-граммам для закона, наивный Байес для общих номеров законов, разрешение отсылок, наследование закона в перечнях. На отложенном test F1 0.956 против 0.659 у правил; на dev 0.990 против 0.854.
- `[важное]` Отложенный test (8 случайных фрагментов, 103 ссылки) размечен и заморожен до экспериментов, прогнан один раз для четырёх финалистов. Правила теряли на нём 0.195 F1 относительно dev, победитель 0.034: правила были подогнаны под текст задания сильнее, чем генератор синтетики под dev.
- `[полезное]` Размеченных токенов нет, поэтому HMM обучается на синтетике: ссылки из генератора, вставленные в настоящие предложения корпуса без маркеров. Порождающая модель с формами токенов перенеслась на реальный текст, CRF на тех же данных переобучился (0.77 против 0.93 на dev).
- `[полезное]` Первая n-граммная модель дала F1 0.32: add-k с k=0.1 размазал вероятности, а фоновая модель, обученная на решениях, сама предсказывала названия законов. После k=1e-4 и вырезания названий из фона 0.88. Та самая «blunt instrument» из лекции 02.
- `[полезное]` word2vec на 2 млн слов решений: соседи «ук» и «коап» - номера статей, а не другие кодексы. Вектор кодирует контекст употребления, а не имя, для различения 1055 похожих названий не годится.
- `[полезное]` Ошибка в подготовке корпуса: `normalize` переводит `\n` в пробел, документ становился одной строкой, gensim резал её до 10 тыс. токенов. Найдена по слишком хорошему времени обучения и странным соседям.
- `[забавное]` Контекстный Байес сначала не отличал закон об адвокатуре от закона об электронной подписи: в тексте «адвокатом», в названии «адвокатской» и «адвокатуре», леммы разные. Помогли основы из 5 букв.
- `[забавное]` Подвал sudact («Судебная практика по применению норм ст. 200.1, 200.2, 226.1, 229.1 УК РФ») попал в 449 из 452 скачанных решений и чуть не стал частью test.

## 2026-10-01

### Сдача (v1.1.0)

- `[важное]` Критерии проверки: 4 скрытых бенча по 500 текстов, лимит 5 минут, иначе метрики обнуляются. v1.0.1 разбирала текст из условия за 0.5 с, 2000 таких текстов - около 17 минут. Ускорено в 5-10 раз без изменения ответов (транспонирование матрицы названий один раз, точное совпадение префикса с названием без tf-idf, кэш сходства, логарифмы эмиссий HMM один раз): 2000 текстов по ~3 тыс. символов - 11 с, худший случай ~2 минуты. Проверка: `make speed`.
- `[важное]` Кода бейзлайна у нас нет (в архиве задания только шаблон с заглушкой). Калибровка по нашей первой версии на правилах: на том же бенче она в 3-4 раза быстрее итоговой; если бейзлайн (14 с на 4 бенча) по скорости близок к ней, наша оценка на стенде проверки - порядка минуты.
- `[важное]` Опрос нашёл `Статья 20.4 ч. 1 КоАП`, прочитанную как `ч. 1` без статьи. Порядок «статья -> часть» добавлен в генератор синтетики и в декодер цепочек. Метрики dev и test не изменились; test теперь только проверка регрессии.
- `[полезное]` Синтетика для HMM не проходила нормализацию, а рабочий текст проходит: «» в синтетике и `"` в работе. Буквы в кавычках после `п.` терялись. Ошибка жила с первой версии HMM.
- `[полезное]` Первая версия правила «запятая заканчивает цепочку» уронила test до 0.876: запятые внутри списка букв (`пунктами «а», «б» части 2 статьи 105`) отрывали буквы от своей статьи. Разделителем считается только запятая, за которой идёт новый маркер.

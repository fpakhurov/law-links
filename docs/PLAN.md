# homework_1 (law-links): план

## 1. Что берём из 02_03 как практики

- Разделение слоёв: доменная логика в отдельном модуле (как `base.py`), веб-слой тонкий (как `app.py` / `server.py`).
- Интерфейсы через `typing.Protocol` (как `TokenizerProtocol`): экстрактор и резолвер законов заменяемы без правки API.
- Пути от `ROOT = Path(__file__).parent`, никаких относительных `open("law_aliases.json")`.
- Тяжёлое строится один раз и кэшируется: индекс алиасов собирается на старте (lifespan), по аналогии с `.atlas_umap_v1.npy` можно запечь его в образ на этапе `docker build`.
- Type hints, docstring модуля с командой запуска, README с разделами «Запуск / Как пользоваться / Ограничения».
- Закреплённые версии в `requirements.txt` с комментарием о версии Python, минимум зависимостей.
- Из лекций: токенизация и n-граммы (02) для поиска названий законов по окну токенов, косинусная близость (03) как fallback для нечёткого сопоставления названий.

## 2. Структура репозитория

```
homework_1/
  main.py                  # FastAPI: lifespan, DI, /detect, /health
  law_links/

  .github/workflows/ci.yml
```

## 3. Алгоритм

1. Нормализация: `«»“”` -> `"`, NBSP и повторные пробелы, `ё` -> `е`, `№ 20` -> `№20`, словарь опечаток маркеров (`пунта` -> `пункта`).
2. AliasIndex (на старте): каждый алиас -> lower -> токены -> леммы (pymorphy3) -> кортеж лемм. Хранение: dict `первая лемма -> список (кортеж, law_id)`, сортировка по длине. Решает склонения: «Гражданского кодекса Российской Федерации» -> «гражданский кодекс российский федерация».
3. Поиск законов в тексте: токенизация regex-ом, леммы, longest-match по n-граммам лемм. Сохраняем span упоминания.
4. Разбор ссылки: от span закона идём влево по токенам конечным автоматом по иерархии `статья <- пункт/часть <- подпункт`. Между уровнями допускаем служебные слова (`в`, `согласно`), окно ограничено, чтобы не захватить чужую ссылку.
5. Значения: `12`, `4.6`, `43.2-6`, `а`, `30.1`; перечисления через `,` и `и` раскрываются в список.
6. Декартово произведение перечислений -> список LawLink (`пп. 1, 2, 3 п. 2 ст. 3 НК РФ` -> 3 объекта). Порядок как в тексте.
7. Fallback для имени закона: если точного совпадения лемм нет, TF-IDF по символьным n-граммам + косинус с порогом (порог подбирается на эталоне).

## 4. Качество

## 7. Решения, которые нужно зафиксировать (по умолчанию в скобках)

1. Ссылка без статьи, `п. 10 АПК`: (article=None, point_article="10").
2. Неизвестный закон, `рандомного кодекса`, `ФЗ №20-456`: (не возвращать ссылку).
3. Неоднозначный алиас, 580 дублей в словаре, например `ФЗ №7-ФЗ`: (брать законы, у которых алиас совпал полностью, при конфликте первый по id, логировать).
4. Перечисления пунктов `3.345, 23`: раскрывать в отдельные объекты так же, как подпункты (да).
5. `часть` и `пункт` оба пишутся в point_article (да).
6. Дубликаты одинаковых ссылок в тексте: (оставлять все, в порядке появления).
7. Пункт внутри части, `п. 6 ч. 1 ст. 24.5 КоАП`: (часть в point_article, пункт в subpoint_article).
8. Четыре уровня, `пп. "г" п. 6 ч. 1 ст. 81 ТК`: (две нижние единицы, subpoint="г", point="6", часть отбрасывается).
9. Диапазоны `ст. 167-171`, `п. 6 - 8`: (одна строка без пробелов, "167-171", не раскрывать).
10. Порядковые слова, `части первой`: (приводить к цифре "1").
11. Абзацы и примечания, `абз. 1 ст. 394`, `примечание 4 к ст. 158`: (отбрасывать, ссылка на статью).
12. Отсылка без названия, `ст. 19.5 названного Кодекса`, `статьи 81 Кодекса`: (в эталоне считается ссылкой на ближайший упомянутый кодекс, экстрактор пока не поддерживает).
13. `п.п. 3, 4 ст. 487`: (читать как "пункты").

## 8. Фаза 2: открытый вклад (после сдачи задания)

Принцип: каждый метод работает на CPU, ставится одной командой и публикуется в готовом к использованию виде. Тяжёлые LLM в поставку не входят.

### 8.1 Методы и бюджеты

| Метод | Поставка | Размер | Латентность, 5k символов, CPU |
|---|---|---|---|
| rules | пакет `law-links` (pip), зависимости: pymorphy3 | < 20 МБ | < 50 мс |
| ner | rubert-tiny2 BIO-NER, ONNX int8 на HF Hub + парсер значений из rules | ~30 МБ | < 150 мс |
| llm | только в арене как внешний эталон через API, не поставляется | - | - |

Общий интерфейс: `LinkExtractor.extract(text) -> list[LawLink]`, выбор через `EXTRACTOR=rules|ner`.

### 8.2 Артефакты для публикации as is

- PyPI: `pip install law-links`, API `extract(text)`, CLI `law-links detect file.txt`, `[ner]` как extra (onnxruntime, tokenizers, без torch).
- Docker: `ghcr.io/<team>/law-links:rules` и `:ner`, тот же `/detect` на 8978.
- HF Model: ONNX int8 + model card (данные, метрики на gold, ограничения, пример кода).
- HF Dataset: gold + silver, версии тегами, dataset card, CC-BY-4.0.
- HF Space (Gradio): демо, разметка, арена.
- Лицензии: код MIT, данные CC-BY-4.0. Проверить право распространять `law_aliases.json` (получить согласие автора курса) и лицензии rubert-tiny2 / pymorphy3.

### 8.3 Space: разметка и арена

- Разметка: подсветка найденных ссылок, по каждой верно / неверно / исправить поля, кнопка «пропущена ссылка» с выделением фрагмента.
- Арена: два анонимных метода на одном тексте, выбор лучшего, рейтинг Bradley–Terry. Спорные случаи уходят в очередь разметки.
- Хранение: JSONL в HF Dataset через `huggingface_hub.CommitScheduler`.
- Приватность: галочка согласия, маскирование ФИО и адресов (Natasha) до сохранения, в датасет попадает только маскированный текст.
- Контроль качества: перекрытие 2 разметчиками на спорных примерах, контрольные примеры с известным ответом, Cohen's kappa в отчёте релиза.

### 8.4 Данные и обучение

1. Silver: rules по RusLawOD и открытым судебным решениям, отбор по уверенности.
2. Gold: правки из Space, отдельный фиксированный test split, в обучение не попадает.
3. Обучение: rubert-tiny2, token classification (LAW, ART, POINT, SUB), экспорт в ONNX, динамическая int8 квантизация.
4. Релиз только если F1 ner >= F1 rules на gold test; иначе публикуем как экспериментальный.
5. Цикл обновления: новый релиз датасета по мере накопления разметки, переобучение, новые теги модели и образа.

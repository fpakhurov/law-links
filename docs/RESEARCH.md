# Исследование методов извлечения ссылок

Цель: сравнить правила, статистические методы из курса (лекции 02, 03) и байесовские методы на одной задаче и одних данных, оставить в сервисе лучшее.

## Постановка

Экстрактор разбит на три заменяемые части (`research/pipeline.py`):

| Часть | Вход -> выход | Что сравниваем |
|---|---|---|
| ChainFinder | текст -> цепочки `пп./п./ч./ст.` со значениями | regex-грамматика, HMM, CRF |
| MentionFinder | текст -> упоминания закона с law_id | точное совпадение, trie по леммам, tf-idf + косинус, fuzzy, эмбеддинги |
| Linker | цепочка + упоминания -> закон цепочки | ближайший справа + служебные слова, поиск по префиксам контекста, наивный Байес |

Метрика: micro precision / recall / F1 по объектам `LawLink`, точное совпадение всех четырёх полей (`scripts/eval.py`). Дополнительно скорость, мс на 1000 символов.

Корпус не хранится в репозитории: `python -m research.corpus` собирает его заново в `research/data/`.

## Этапы

1. Бейслайны: точное совпадение названий (b0), текущий сервис (b1).
2. Методы курса: tf-idf и косинус (03), fuzzy matching (03, практика), n-граммные модели со сглаживанием (02), word2vec / Navec (03).
3. Байесовские и прочие: наивный Байес, HMM (Витерби), CRF, логистическая регрессия.
4. Тюнинг лучших на dev, комбинирование частей.
5. Однократная проверка финалистов на test, выбор, перенос в `law_links`, удаление остального.

## Журнал

- b0 -> b1: морфология даёт +0.07 F1, почти целиком за счёт полноты («Налогового кодекса», «Трудовым кодексом»).
- s1_tfidf: полнота +0.09 к b1. Закрывает `КоАП` без `РФ`, `Закона N 27-ФЗ`, дату и номер между цепочкой и названием. FP растут с 11 до 18, скорость падает в 20 раз. Параметры почти не влияют: F1 0.883-0.895 при пороге 0.6-0.9 и любых n-граммах.
- s3_ngram, первая версия: F1 0.32. Две ошибки постановки: add-k с k=0.1 при словаре 3 тыс. слов размазывает вероятность (биграмма «гражданский кодекс» у ГК получала 0.012), а фоновая модель, обученная на решениях, сама хорошо предсказывает названия законов и гасит LLR. Исправлено: k=1e-3..1e-4, из текста для фоновой модели вырезаются найденные названия законов (фон = гипотеза «не закон»). После исправления 0.884. Остаточные FP: одно редкое «законное» слово даёт большой LLR («п. 7.1 Договора», «п. 69 Правил»).
- s4_w2v: соседи «ук» и «коап» в word2vec - номера статей, а не другие кодексы: вектор кодирует контекст употребления, а не название. Для различения 1055 похожих названий средний вектор слишком грубый, сам по себе метод хуже всех; в смеси с tf-idf прироста нет.
- Ошибка подготовки корпуса: `normalize` превращает переводы строк в пробелы, документ становился одной строкой, gensim обрезал её до 10 тыс. токенов. Исправлено, модели пересчитаны.
- c_hmm: второй порядок лучше первого на 0.04. С одной предыдущей меткой модель не отличает `п. 6 ч. 1` (пункт внутри части) от `ч. 3, ч. 4` (перечень частей). HMM2 закрывает точку после номера, буквы в кавычках, пункт в части, четыре уровня, порядковые слова.
- Остаточные ошибки HMM2: несколько цепочек перед одним законом (задача связывания, не разметки), абзацы (`абз. 1 ст. 394` -> пункт 1), формы «подпунктах», неоднозначный номер закона (`63-ФЗ`: 246 или 396).
- c_crf: ошибается на длинных перечнях (`ст. ст. 4, 64, 65, 71, 101, 102 АПК РФ` -> середина списка размечена пунктами): признаки окна ±3 не видят маркер в начале списка, признак-слово запоминает числа из синтетики (`low:11.8.4`). В работе: признак-слово только для буквенных токенов, подбор c1/c2.

## Статус (2026-09-29) и следующие шаги

Лучшее на dev: HMM2 (цепочки) + tf-idf (закон), F1 0.919. test не запускался ни разу.

1. CRF: пересчитать после маскирования числовых признаков (`python -m research.bench "c_crf?c1=0.5&c2=0.5"`).
2. Связывание: цепочка без закона наследует закон следующей цепочки через запятую или «и» (`ч. 6 ст. 15, ст.ст. 64 и 73 УК РФ`), для всех вариантов.
3. Генератор HMM: абзацы как отбрасываемый уровень, формы «подпунктах/пунктах/частях», обратный порядок `п. 2 пп. 2`, больше `п. 10 АПК` без статьи.
4. Наивный Байес по контексту для неоднозначных номеров законов (`63-ФЗ`: 246 / 396), байесовский линкер по словам между цепочкой и законом.
5. Тюнинг regex-грамматики (rules v2) как сильный бейслайн против HMM2.
6. Финалисты -> один прогон на test -> перенос лучшего в `law_links`, удаление остального, обновление README и тестов.

Воспроизведение: `pip install -r research/requirements.txt`, `python -m research.corpus` (+ арбитражные id из журнала коммитов), затем `python -m research.bench`.

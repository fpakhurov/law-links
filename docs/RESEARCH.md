# Исследование методов извлечения ссылок

Цель: сравнить правила, статистические методы из курса (лекции 02, 03) и байесовские методы на одной задаче и одних данных, оставить в сервисе лучшее.

## Постановка

Экстрактор разбит на три заменяемые части (`research/pipeline.py`):

| Часть | Вход -> выход | Что сравниваем |
|---|---|---|
| ChainFinder | текст -> цепочки `пп./п./ч./ст.` со значениями | regex-грамматика, HMM, CRF |
| MentionFinder | текст -> упоминания закона с law_id | точное совпадение, trie по леммам, tf-idf + косинус, fuzzy, эмбеддинги |
| Linker | цепочка + упоминания -> закон цепочки | ближайший справа + служебные слова, поиск по префиксам контекста, наивный Байес |

Метрика: micro precision / recall / F1 по объектам `LawLink`, точное совпадение всех четырёх полей (`scripts/eval.py`). Дополнительно скорость, мс на 1000 символов.

## Данные

| Набор | Состав | Ссылок | Назначение |
|---|---|---|---|
| dev | `tests/gold.json` + `tests/gold_real.json` | 256 | подбор методов и параметров, разбор ошибок |
| test | `tests/gold_test.json`: 8 случайных фрагментов решений (6 суды общей юрисдикции, 2 арбитраж) | 103 | отложен, запускается только для финалистов |
| корпус | 452 решения с sudact.ru (427 общей юрисдикции из 48 тем практики, 25 арбитражных), 15 млн символов, без разметки | - | обучение моделей без учителя; документы test исключены (`research.corpus.training_texts`) |

dev уже использовался для разбора ошибок экстрактора, поэтому честную оценку даёт только test. Документы test выбраны из корпуса случайно (`python -m research.sample_test`, seed 20260929, случайное окно ~8 тыс. символов из каждого документа, чтобы не выбирать самые плотные по ссылкам части), размечены вручную до запуска на них любых методов и заморожены: sha256 `tests/gold_test.json` = `4fc9aaf7…73a4f`. Разметка следует тем же правилам, что dev (PLAN.md, раздел 7); отсылки без названия закона и без отсылочного слова («(статья 1089)» внутри цитаты) не размечаются.

Корпус не хранится в репозитории: `python -m research.corpus` собирает его заново в `research/data/`.

## Этапы

1. Бейслайны: точное совпадение названий (b0), текущий сервис (b1).
2. Методы курса: tf-idf и косинус (03), fuzzy matching (03, практика), n-граммные модели со сглаживанием (02), word2vec / Navec (03).
3. Байесовские и прочие: наивный Байес, HMM (Витерби), CRF, логистическая регрессия.
4. Тюнинг лучших на dev, комбинирование частей.
5. Однократная проверка финалистов на test, выбор, перенос в `law_links`, удаление остального.

## Журнал

- b0 -> b1: морфология даёт +0.07 F1, почти целиком за счёт полноты («Налогового кодекса», «Трудовым кодексом»).
- s1_tfidf: полнота +0.09 к b1. Закрывает `КоАП` без `РФ`, `Закона N 27-ФЗ`, дату и номер между цепочкой и названием. Цена: FP растут с 11 до 23, скорость падает в 30 раз. Оставшиеся FN почти все из грамматики цепочек (`п. «б»`, `п. 6 ч. 1`, несколько цепочек перед одним законом), а не из распознавания закона.
